**Hera Agent Godot** lets AI coding agents inspect and control a **live Godot editor** in real time — instead of guessing scene structure from stale training data, the agent acts on the *real* editor and checks the result. **Verified on every stable from Godot 4.2 to 4.7.**

This Asset Library entry is the **editor addon** (the in-editor bridge). The companion **`hera` CLI** lives on GitHub and is what the agent actually runs.

## Why a CLI, not MCP?

Godot already has a healthy MCP-addon ecosystem — Hera makes the opposite bet on purpose. MCP servers pay for breadth in tokens: dozens to 100+ tool schemas plus verbose JSON responses sit in the agent's context every turn.

Hera delivers **MCP-grade reach over the live editor as a compact-JSON-by-default CLI** — one command per action, minimal tokens, and it works with anything that can run a shell command (pipes, `batch`, CI, any agent), not just MCP clients. The agent loads **zero tool schemas**: the only resident surface is one small cacheable doc (~1k tokens) that stays flat no matter how many commands exist.

## What the agent can do

- **Read the editor** — live status, scene tree, node properties, open scenes, selection, focused scripts, resources, Theme items, and ClassDB metadata.
- **Edit the scene** — add / instance / set / reparent / remove nodes, attach & detach scripts, wire resources, connect & disconnect signals. Editor node and signal writes are undoable steps (Ctrl+Z).
- **Scripts & project** — create GDScript or C# by filename, validate on-disk GDScript with the connected editor's engine, manage project files and folders, scan/reimport resources, refresh UIDs, and set the main scene.
- **Inspect and edit Themes** — read or update Godot `Theme` colors, constants, and font sizes through the engine's per-type Theme maps.
- **Run GDScript** — evaluate an expression against the edited scene through an `EditorInterface` proxy.
- **Drive a running game** — inspect and mutate the runtime tree, pause and step the play clock, click controls, inject keyboard/mouse/joypad input or physics-frame sequences, read the runtime UI tree, and assert on state.
- **Proof-first QA** — capture and analyze screenshots at the live viewport size, compare captures locally, run requirement-covered QA scenarios, and get a one-shot runtime health verdict with `game qa diagnose`.
- **Diagnostics** — tail the effective Godot log with error/warning filters and summarize problems without false-clean results.

## New in v1.1.0 — languages, play clock, and isolated runtimes

- **GDScript and C# by filename.** `script create` / `open` / `attach` take `.gd` or `.cs`. Optional `--lang` must match. C# needs Godot .NET and a loaded assembly; Hera does not generate solutions or run builds.
- **Play clock.** `game clock` reads or sets `SceneTree.paused` and `Engine.time_scale`, and `--step` advances one process or physics frame. The runtime inspector keeps answering while paused.
- **Joypad input and sequences.** `game input joypad` / `axis` inject Godot joypad events. `game input sequence` replays bounded InputMap actions on physics frames.
- **Undoable reparent.** `node reparent` uses `Node.reparent` and restores owners and names on undo.
- **Script validate.** `script validate` runs the connected editor's Godot binary `--check-only` on a project script and returns the engine exit and bounded output.
- **Isolated game processes.** `game --pid` selects one live runtime. Missing or expired PIDs fail instead of falling back. Parallel games that share `user://` are flagged.
- **Honest captures and editors.** Runtime screenshots report live PNG size without upscaling. Expired editor heartbeats list as `stale` instead of "no editor".
- **Safer writes.** Removal and reparent undo preserve subtree ownership. Resource and theme batches validate before mutation. A configured auth token that cannot be read refuses startup. QA scenarios preflight before they hit the editor.

Upgrade the CLI and addon together, fully restart Godot, then run `hera status` and `hera smoke --skip-game`. Existing scenes, opt-in auth, and the transitional `hera-agent-godot` alias remain compatible. Experimental command shapes may still evolve; documented stable fields keep the v1 promise.

## Command surface

`status`, `instances`, `run` / `stop`, `scene`, `editor`, `script` (including `validate` and `.gd`/`.cs`), `project`, `classdb`, `node` (read + write + reparent + resource/script wiring), `signal`, `resource`, `theme`, `game` (runtime inspect + clock + input + joypad/axis + sequence + input-log + set/call/click + assert + QA + screenshot), `guidance`, `game_feel`, `output`, `diagnostics`, `eval`, `screenshot` (capture + local diff), `batch`, and `smoke` — with `--json` and `--ids` output modes plus `--instance` and `--timeout` global flags; compact JSON is the default.

## How it works

The addon is an `@tool` `EditorPlugin` that runs a localhost HTTP server and advertises the editor to the CLI via `~/.hera-agent-godot/instances/`. The Go CLI discovers the editor and sends one compact JSON request per command, executed on the editor main thread through `EditorInterface`. No cloud and no account — everything stays on localhost, optionally behind the shared token.

## Install

1. Use any **Godot 4.2–4.7** stable build (4.7 recommended — it gets the full QA treatment; see `docs/SUPPORT_MATRIX.md` in the repo).
2. Copy `hera_agent_godot/` into your project's `res://addons/`.
3. Enable **Project → Project Settings → Plugins → Hera Agent Godot**.
4. Grab the `hera` CLI from GitHub (one-line installer, `npm`, `brew`, `scoop`, or `go build`) and start driving the editor from your agent.

## Changelog

### Languages and scripts

- Select GDScript or C# by the `.gd` / `.cs` extension on create, open, inspect,
  and attach. Optional `--lang` must match the extension.
- C# templates use a filename-matching partial class. Attachment requires Godot
  .NET and a loaded assembly; Hera does not generate `.csproj` files or run
  builds.
- Add `script validate` to run the connected editor's engine `--check-only` on
  an on-disk GDScript file and return the exit status plus bounded engine output.

### Play clock and input

- Add `game clock` for `SceneTree.paused`, `Engine.time_scale`, and one-frame
  `--step` / `--physics`. The runtime inspector uses `PROCESS_MODE_ALWAYS` and
  wall-clock heartbeats so a paused or scaled game still answers.
- Add `game input joypad` and `game input axis` using
  `InputEventJoypadButton` / `InputEventJoypadMotion`.
- Add `game input sequence` to replay a bounded list of InputMap actions on
  physics frames, with cleanup and cancellation if the clock changes.

### Scene edits and ownership

- Add undoable `node reparent`, defaulting to `Node.reparent`'s global-transform
  keep. Undo restores parent, sibling index, owners, and the original name after
  a collision rename.
- Preserve descendant owners when undoing node removal. Reject resolved root
  aliases that would mutate the scene root by another path.

### Isolated runtimes and honest sizes

- Select a live game with `game --pid`. Missing or expired PIDs fail instead of
  falling back. Parallel processes that share `user://` set `shared_user_data`.
- Exclude Hera's owned runtime inspector autoload from exported project
  settings, then restore it for editor play.
- Runtime screenshots report live PNG, window, visible-rect, and project
  viewport sizes without upscaling. `size_matches_project` compares PNG pixels
  to the project viewport.
- `hera instances` lists expired editor heartbeats under `stale`. `--instance`
  against an expired pid says so instead of "no live Godot editor found".

### Safer resources, HTTP, and QA

- Validate complete resource and theme property batches before any setter runs.
- Publish runtime request files atomically. Bound HTTP response writes so a
  slow client does not stall the editor tick.
- Refuse plugin startup when a configured auth token file cannot be read.
- Preflight `game qa --file` scenarios and reject unavailable or invalid
  diagnostic evidence as coverage.
- Set the main scene through the live editor instead of a duplicate project-file
  writer.
